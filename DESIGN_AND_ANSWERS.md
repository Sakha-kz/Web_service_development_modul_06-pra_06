# Отчёт и ответы на контрольные вопросы: Модуль 06 (Практическая работа)

## 📌 Архитектурные решения

В рамках практической работы реализованы два основных механизма контроля доступа к ASP.NET Core Web API:
1. **Аутентификация по сервисному ключу (API Key):**
   - Реализована через кастомный фильтр авторизации `ApiKeyAttribute : Attribute, IAuthorizationFilter`.
   - Проверяет заголовок `X-Api-Key`. При несовпадении или отсутствии прерывает конвейер со статусом `401 Unauthorized`.
2. **JWT-аутентификация (Bearer Token):**
   - Настроена через middleware `Microsoft.AspNetCore.Authentication.JwtBearer`.
   - Включает проверку издателя (`Issuer`), аудитории (`Audience`), криптографической подписи (`IssuerSigningKey`) и времени жизни токена (`ValidateLifetime` с `ClockSkew = TimeSpan.Zero`).
   - Эндпоинты защищены декларативным атрибутом `[Authorize]`.

## ❓ Ответы на вопросы по безопасности

### 1. Что представляет собой JWT-токен и из каких частей он состоит?
JWT (JSON Web Token) состоит из трех частей, разделенных точками (`.`):
1. **Header (Заголовок):** содержит тип токена (`JWT`) и алгоритм хеширования подписи (например, `HS256`).
2. **Payload (Полезная нагрузка):** содержит клеймы (Claims) — утверждения о пользователе (`sub`, `name`, `role`), идентификатор токена (`jti`) и временные метки (`iss`, `aud`, `exp`, `nbf`).
3. **Signature (Цифровая подпись):** формируется путем хеширования Base64-кодированных Header и Payload с использованием секретного ключа сервера (`HMACSHA256(base64(header) + "." + base64(payload), secret)`). Защищает токен от подделки.

### 2. Зачем нужен параметр `ClockSkew` при валидации JWT?
По умолчанию ASP.NET Core добавляет временной допуск (5 минут) для компенсации возможной рассинхронизации часов между сервером авторизации и сервером ресурсов. Установка `ClockSkew = TimeSpan.Zero` отключает этот зазор, гарантируя, что токен станет недействительным ровно в секунду, указанную в поле `exp`.

### 3. В чем разница между API Key и JWT?
* **API Key:** статическая строка, идентифицирующая клиентское приложение или проект. Обычно не содержит информации о конкретном пользователе, не имеет встроенного срока жизни и требует хранения на сервере в белом списке.
* **JWT:** самодостаточный (self-contained) криптографически подписанный токен, инкапсулирующий данные пользователя и его роли, ограниченный по времени жизни и не требующий постоянного обращения к базе данных для проверки подлинности.
